`127.0.0.1` или `localhost` и на нём обнуляет паузы. Выставь кто-нибудь
`OZON_API_URL` на боевой хост — и паузы исчезли бы разом у отправлений и
возвратов, поэтому проверка именно на localhost, а не «задана ли переменная».

| `POST /v1/order/fbo/list` | заказы FBO по дате изменения | `mvideo.js` |

| `POST /v1/merchant/location/list` | имена FBS-складов | `mvideo.js` |

| `POST /v1/product/mapping/list` | артикул ↔ ID товара для каталога | `mvideo.js` |

Ключ — в `api-key`; на 401/404/`400 OPERATION_NOT_SUPPORTED` запрос повторяется с одним `Authorization: Bearer` (стандарт omninet); прошедшая схема запоминается для метода; если не прошла ни одна, решает `api-key` (Bearer — только при 401 на `api-key`). 404 на `/v1/order/fbo/list` адрес шлюза не меняет; неподключённый DBS — 404, 403 или решающий `400 OPERATION_NOT_SUPPORTED`. На запасной `api.omniom.ru` — оба заголовка. Плюс обязательный `User-Agent`.
Первая страница на «HTTP 400» пробуется в трёх видах тела; прошедший вид запоминается.
Адресов два (`omni-net.sellers.mvideo.ru`, `api.omniom.ru`), первый ответивший запоминается.
FBO — по стандарту omninet: заказы `POST /v1/order/fbo/list`, имена складов площадки
`POST /v1/market/location/list`, остатки — тем же `stock/info`, строками со складом площадки;
если их нет без фильтра — запросом в форме FBO, с `filter.market_location_ids` по справочнику.
Подключён ли FBO кабинету, говорит сам шлюз: `400 OPERATION_NOT_SUPPORTED` или 404.
Ошибка запроса называет адрес в квадратных скобках; запасной адрес помечается в «Результате».

## 4. Листы книги

### Задачи и листы

Обычно имя задачи совпадает с именем листа. Единственное исключение: задача
`Возвраты OZON FBS` пишет в лист `Возвраты OZON` — возвраты приходят одним
методом сразу по обеим схемам.

| Задача | Лист | Режим | Ключ (индексы колонок) |
|---|---|---|---|
| FBO остатки ВБ | тот же | снимок | — |
| FBS остатки ВБ | тот же | снимок | — |
| Заказы ВБ FBO | тот же | дозапись | `[0]` srid |
| Заказы ВБ FBS | тот же | дозапись | `[0]` задание |
| FBS Возвраты | тот же | дозапись | `[0,2]` возврат + баркод |
| WB заказы проверка | тот же | дозапись | `[0]` srid |
| FBO остатки ОЗОН | тот же | снимок | — |
| FBS остатки ОЗОН | тот же | снимок | — |
| Заказы ОЗОН FBO | тот же | дозапись | `[0,4]` отправление + артикул |
| Заказы ОЗОН FBS | тот же | дозапись | `[0,4]` |
| **Возвраты OZON FBS** | **Возвраты OZON** | дозапись | `[0]` возврат |
| FBO/FBS остатки Яндекс | тот же | снимок | — |
| Заказы Яндекс FBO/FBS | тот же | дозапись | `[0,2]` заказ + артикул |
| FBO/FBS остатки Ламода | тот же | снимок | — |
| Заказы Ламода FBO/FBS | тот же | дозапись | `[0,2]` |
| FBO остатки Мвидео | тот же | снимок | — вручную: FBO в API нет |
| FBS остатки Мвидео | тот же | снимок | — |
| Заказы Мвидео FBO | тот же | дозапись | — вручную: FBO в API нет |
| Заказы Мвидео FBS | тот же | дозапись | `[0,2]` заказ + артикул, FBS и DBS |
| Каталог | «Каталог» + «Штрихкоды» | снимок | — раз в сутки, время в колонке D |

Снимок — любой лист, в имени которого есть слово «остатки» (`СНИМКИ`,
`schemas.js`).

### Значения перечислений ленты заказов

В лист они уходят **как есть**, без перевода: так их можно сверять с другими
листами. Расшифровка из спецификации метода:

| `status` | Значит |
|---|---|
| `created` | оформлен |
| `buyout` | продан |
| `cancel` | отменён |
| `return` | возвращён |
| `returnDefective` | возвращён по причине брака |

| `cancelType` (только при `cancel`) | Значит |
|---|---|
| `app` | отказ до получения |
| `receipt` | отказ при получении |
| `expire` | истёк срок получения |
| `other` | техническая отмена |

Колонка «Схема» выводится из `isMp`: `true` — склад продавца (FBS), `false` —
склад WB (FBO).

### Колонки

Полные схемы — в `src/schemas.js`, раздел `СХЕМЫ`. Там же единственный источник
правды по порядку колонок; дублировать его здесь значило бы завести второе
место, где он расходится с кодом.

Два правила, общие для всех листов:

* **«Обновлено» всегда последняя.** Сравнение строк её игнорирует — иначе
  каждый прогон считал бы изменившимися все строки.
* **Правее колонок схемы лежат служебные колонки книги** — ключи окна, недели,
  месяца. Их считают формулы, сервис до них не дотягивается: ширина записи
  ограничена длиной схемы.

### Лист «Настройки»

| Что | Диапазон | Константа |
|---|---|---|
| Имя листа | `Настройки` | `НАСТРОЙКИ.лист` |
| Параметры | `A3:B12` | `параметрыОт` / `параметрыДо` |
| Блок задач | `A15:G62` | `задачиОт` / `задачиДо` |
| Дочитывается ниже блока | ещё 5 строк | `задачиЗапас` |
| Куда пишется итог | `F{строка}:G{строка}` | `config.js` |

**Сдвигать строки на листе нельзя** — сервис читает их по номерам.

Пять строк ниже блока дочитываются не ради работы, а ради предупреждения: задача,
вписанная за концом блока, иначе не запустилась бы и ничего бы об этом не сказала.
Имена задач — замкнутый список, поэтому ложной тревоги на чужих блоках листа быть
не может. Завели задачу в строке 62 — поднимите `задачиДо` в `src/schemas.js`.

## 5. Числовые пределы

### Запись в книгу (`sheets.js`)

| Константа | Значение | Смысл |

| Константа | Значение | Смысл |
|---|---|---|

| пауза между страницами | `300` мс | везде |

## 6. Коды ответов, на которые есть особая реакция

| Код / признак | Где | Что делаем |
|---|---|---|
| `408`, `425`, `429`, `≥500` | `http.js` | повтор с растущей паузой |
| прочие `4xx` | `http.js` | сразу наружу, повтор не поможет |
| пустое тело / `204` | `http.js` | отдаём `{}` |
| ответ не JSON | `http.js` | ошибка с куском тела |
| `0` строк в снимке | `sheets.js` | **ошибка**, лист не перезаписываем |
| ответ без `postings` | `wb-ozon.js` | **ошибка**, а не «конец окна» |
| ответ без `returns` | `wb-ozon.js` | **ошибка**, а не «возвратов нет» |
| ответ без `report` | `wb-ozon.js` | **ошибка**, а не «возвратов нет» |
| курсор не двигает выборку | `wb-ozon.js` | **ошибка**, а не бесконечный круг |
| ответ ленты без `orders` | `wb-ozon.js` | **ошибка**, а не «заказов нет» |
| страница ленты повторяет предыдущую | `wb-ozon.js` | **ошибка**: `offset` застрял |
| нет `snapshotTime` при продолжении выборки | `wb-ozon.js` | **ошибка**: листать по живым данным нельзя |
| `snapshotTime` ответа не тот, что просили | `wb-ozon.js` | **ошибка**: метод переснял данные, нумерация чужая |
| страница ленты уже приходила | `wb-ozon.js` | **ошибка**: выборка ходит по кругу |
| `429` у ленты заказов | `wb-ozon.js` | ошибка с объяснением: лимит зависит от категории токена |

Общее правило: **молчаливая потеря данных хуже честного падения.** Пустой
ответ, который можно спутать с «данных нет», везде превращается в ошибку — иначе
сбой у маркетплейса записался бы в книгу как успешный прогон.

## 8. Регулярные выражения

| Выражение | Где | Что ловит |
|---|---|---|
| `/^[=+\-@]\|^0\d\|^\d{1,4}[-./]\d{1,2}[-./]\d{1,4}\|^\d{1,4}[-/]\d{1,2}$\|^\d{1,2}:\d{2}/` | `http.js` | значения, которые Таблицы переиначат |
| `/^\d{1,2}\.\d{1,2}\.\d{4}(?: …)?$/` | `sheets.js` | дата, записанная нами текстом |
| `/\\\|\s*успех:\s*(…)/` | `config.js` | метка успеха в «Результате» |
| `/^(\d+)/` | `config.js` | глубина из текста «31 д» |
| `/^https?:\/\/(127\.0\.0\.1\|localhost)[:/]/` | `wb-ozon.js` | подставной адрес в пробе |

Точка в первом выражении намеренно **не** ловит двухчастные значения: `3.7` и
`100.50` — обычные числа, а через `текстом()` проходят и числовые колонки.
